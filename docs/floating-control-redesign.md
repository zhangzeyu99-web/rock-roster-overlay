# 直播快捷控制悬浮窗重做基准

## 目标

把悬浮窗从“深色工具弹窗”重做为“直播中可用的半透明控制台”。

目标图特征：

- 更窄更高，贴近直播侧边悬浮控制台；双方阵容不应被窄窗口压缩。
- 背景有明显虚化，面板有透明、反光、边缘高光和层次。
- 左队/右队通过红蓝阵营色建立语义。
- 队伍列表是稳定表格行，不是卡片套卡片。
- 形态选择、战败状态、快捷导入、选手名和比分都是直播中高频操作，必须一眼可用。

## 当前问题

1. **整体比例错误**
   - 旧版默认宽度 420px，信息被压缩，右队需要滚动。
   - 最终默认尺寸改为约 560 x 1180，贴近设计稿窄高比例。

2. **玻璃质感不足**
   - 当前只是深灰半透明卡片。
   - 设计稿是背景虚化、顶部反光、内阴影、边缘高光组合出来的玻璃面板。

3. **风格误判**
   - 当前偏 Raycast/开发者工具风格，冷、硬、紧凑。
   - 目标应偏游戏直播 HUD，轻、通透、有阵营色和比赛感。

4. **按钮层级错误**
   - “填左队 / 填右队”不应是白色普通按钮。
   - 应分别使用红色和蓝色主按钮，对应左右阵营。

5. **队伍区结构错误**
   - 当前每队是卡片容器，行内元素拥挤。
   - 应改成表格行：序号、头像、名称、形态、战败，行间细分割线。

6. **序号设计错误**
   - 当前只是小数字，识别弱。
   - 应为方形胶囊，左队红、右队蓝。

7. **比赛信息区缺少赛事感**
   - 当前是普通输入表单。
   - 应为红蓝左右分区，中间显示 VS。

8. **原生 select 风险**
   - Windows/Chromium 下原生下拉可能出现系统白底，和自定义深色主题冲突。
   - 应改为自定义下拉浮层，彻底避免白底白字和样式不可控。

## 重做标准

### 窗口

- 默认尺寸：约 560 x 1180。
- 最小尺寸：至少 500 x 720。
- 无边框、透明、可拖拽、可置顶。
- 背景不应完全不透明，必须保留直播画面/主界面的虚化穿透感。

### 顶栏

- 左侧：图标、标题、同步状态。
- 右侧：置顶、最小化、关闭。
- 顶栏要有分割线和轻反光，不能像普通网页标题栏。

### 快捷导入

- 一行输入框。
- 左右两个主按钮使用阵营色：
  - 左队：柔和红。
  - 右队：直播蓝。

### 队伍列表

- 左右队各一组。
- 分区标题含阵营色圆点和 `6/6`。
- 每行结构固定：
  - 阵营色序号胶囊。
  - 精灵小头像。
  - 精灵名。
  - 自定义形态下拉。
  - 战败勾选。
- 行间用细分割线，不用重卡片边框。

### 自定义形态下拉

- 关闭态：深色玻璃按钮。
- 打开态：同一视觉系统的深色浮层。
- 选中项用蓝色高亮，文字必须始终可读。
- 不再依赖原生 `select option`。

### 比赛信息

- 底部做成左右阵营分区。
- 左侧红、右侧蓝，中间 `VS`。
- 选手名和比分输入应比普通表单更像直播控制项。

## 验收点

- 截图对比时，第一眼应接近目标图的“直播控制台”，不是后台工具面板。
- 不出现白底白字。
- 窗口打开后能完整看到核心操作，尽量减少滚动。
- 左右阵营色一眼可辨。
- 快捷导入、形态切换、战败、选手名、比分全部可操作。
- 主窗口点击“快捷控制”重复点击仍只聚焦已有窗口，不重复创建。

## v3.2.1 自查结论

- 默认 560px 宽不再触发移动断点，快捷导入保持一行布局。
- 12 个阵容槽位、形态下拉、战败勾选和比赛信息区在默认窗口内完整显示。
- 玻璃面板增加背景虚化、顶部反光、边缘高光和底部暗角；当前浏览器截图可验证内部比例和控件层级，Electron 透明窗口会叠加真实桌面/游戏背景。
- 自定义下拉继续保留，打开态不出现白底白字。
