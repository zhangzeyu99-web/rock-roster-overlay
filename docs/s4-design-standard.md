# S4 主题设计与验收标准

触发条件：以后新增或替换精灵衬板、标题、选手栏，以及调整它们的尺寸、位置、层级时，均执行本清单。

## 精灵优先

- 衬板的作用是在精灵后面提供干净、平面的识别背景；不限定为云朵。
- 不做托举精灵的立体台座，不加厚重侧面、大面积花纹或突出的金色装饰。
- 判断依据是精灵在真实游戏画面中的清晰度、相邻卡片间距和整体协调，而非底板单独展示是否华丽。
- 先看当前项目的真实合成画面，再改素材；生成素材后必须接回实际组件看效果，不能只交一张独立素材图。
- 衬板与精灵一并缩放，人物识别特征与姓名可读；赛季装饰主要由标题和选手栏承担。

## 本轮确定的视觉

- S4「月涌狂想」：月白、灰蓝、少量浅金；标题提供美术字标与系统字标（可编辑）两种模式。
- 衬板采用低对比平面浅色背景、柔和轮廓、极淡月纹；视觉层级低于精灵。
- 选手栏采用浅色姓名区域、深蓝中央比分区域，VS 和赛制居中。
- 新项目默认 S4；旧项目未指定主题时保持 S3，可切回 S3 或单独混搭。

## 验收清单

- 弧形、垂直两套布局，各覆盖 1920×1080 和 2560×1440。
- 每种组合检查真实游戏画面合成与透明输出，确认顶部游戏 UI 安全区、末卡和选手栏的距离。
- 左队、右队、双方、直播间导出分别核对尺寸、角落透明度和资源完整性。
- 实际打开桌面捕获窗口并关闭，核对开关状态；编辑后检查 OBS 页面实时同步。
- 切主题、切排布、切分辨率不能丢自定义标题、阵容和附加文本；保存重载后保持。
- 从真实控件调整左右姓名、比分、VS 和赛制，检查实际渲染值，不能只验证配置 JSON。
- S4 视觉与主流程由 Astra 复核；保留合成图与确定性检查报告。

## 可重跑入口

```powershell
npm test
npm run e2e
npm run build
node scripts/verify-s4-runtime.mjs
```

原生验证脚本使用项目 tmp 内隔离 documents/userData，不覆盖日常项目配置。证据写入 `release-evidence/s4-development`。新素材属于基于赛季主题创作的 UI 图，不冒充官方原图；精灵素材继续使用现有资料库，未补录缺失 S4 精灵数据。

## 中央计分区补充门禁

- 触发：更换底栏素材或调整比分、VS、赛制时，按素材实际净空测量，不把月牙、边框和星尖当作文字区域。
- S4 中央计分区只使用整栏约 18%，文字净空约 x=42%..58%；VS/赛制整组上移，避开底部星尖。
- 必须逐张看 770×434 小预览下的 0:0、12:9、999:1 和空赛制；e2e/s4-theme.spec.ts 按字体实际墨迹边界检查，不以元素外框代替文字碰撞检查。

## 衬板重设计与精灵重叠修正（v3.6.1）

- 新 S4 底框必须直接出现在「底框」下拉选项中，分别命名「S4 · A 月环留白」「S4 · B 星轨横签」「S4 · C 月窗徽章」；不能要求用户先猜测「柔和云朵」再找赛季子选项。
- 当前 S4 使用 `public/card-plates/s4-moon-ring.png`、`s4-star-pennant.png`、`s4-moon-window.png` 三个已确认素材，默认 A；旧 S4 未记录分支时采用 A，旧 S3 保持 S3。三个方案都保持平面衬托。
- 1080p 预设：精灵比例 0.90、槽间额外间距 14；1440p：比例 0.94、额外间距 12；两尺寸衬板比例 0.96、偏移 0。两种排布均应用。
- S4 精灵按透明通道的实际可见轮廓适配槽位，1440p 与1080p保持接近的屏占比；保留用户自定义缩放能力。
- 识别旧 S4 默认组合并迁移到新预设，避免升级后仍保留上一版的重叠布局；非默认自定义组合保留。
- 验收必须检查相邻槽位之间的精灵、衬板、姓名栏、属性徽章交叉重叠，不能只验证云朵/底板边界。
- `e2e/s4-roster-spacing.spec.ts` 以真实精灵图 alpha>=32 的像素和实际标签轮廓进行检查，三种衬板 × 四组预设须 overlaps=0；全尺寸与770小预览均需看图。CSS外投影不计作主体重叠。


## 标题双模式与美术字门禁（v3.6.2）

- 触发：用户要求赛季美术字重设计，或修改标题模式、素材和切换交互时。
- 美术字应从四字整体笔势与轮廓设计，减少逐字金属渐变、厚描边和 PPT 式浮雕效果。
- 在「装修 → 赛季标题」直接提供互斥的「美术字标」「系统字标（可编辑）」入口，不能用隐藏图片的操作代替模式说明。
- 美术模式展示素材选择，系统模式展示标题文字输入。切模式保留原文字、字体、颜色、坐标、字号与图片设置；不得悄悄重置样式。
- S3/S4 内置字标随赛季切换；用户导入素材和自定义位置保持。重载后选中状态应与当前可见模式一致。
- 生成字标必须检查真正的 alpha 通道，禁止使用画有棋盘格的不透明图片；通过实际明暗背景合成判断边缘，不仅看透明图查看器。
- 两个尺寸都检查 770 宽小预览、实际游戏合成、系统文字修改、美术/系统往返切换与保存重载。
- 自动门禁：`e2e/s4-theme.spec.ts` 验证双模式与重载；`scripts/verify-s4-runtime.mjs` 验证内置标题原生导出与真实透明度。


## 选手名向内对齐（预览迭代）

S4 选手名从中央比分区向外展开：左名右对齐、右名左对齐，保留内侧安全间隔。以后修改姓名字号、底栏宽度或头像布局时，检查 1920×1080 与 2560×1440 的实际底栏，避免碰到中央月牙或比分。


## 视觉迭代与出包边界

用户指出视觉微调不应急着出包。后续视觉反馈默认只修改项目并提供实际预览，不自动递增版本号、不构建安装包、不进入发布验收；只有用户明确要求定稿出包或打包时才执行。验收方式：本轮只需相关画面检查，交付动作必须能对应用户的明确要求。


## 中央区双版式

提供「仅 VS / VS＋比赛局数」明确入口。仅 VS 与比分同排居中，带局数采用上下两行；开关独立于比赛局数内容，来回切换保留文字。调整入口、字号说明和两种实际预览必须一起交付，视觉迭代不触发打包。


## A/B/C 分支选择验收

- 三个选项直接可见，不隐藏在云朵子菜单；分别保存为 moon-ring、star-pennant、moon-window。
- 换衬板只改变素材与对应版式，不重置精灵大小、间距、底板比例、偏移或标题。分辨率预设按原规则应用，但保留衬板选择。
- B 横签在 1080p 设计空间中下移 24px，1440p 按输出比例同步缩放；A/C 使用完整浅色衬托轮廓。
- 通过真实控件逐一切换、保存重载、切换 1920×1080 与 2560×1440，并检查 S3/透明模式往返。
- 对比图由 `docs/design-options/s4-plates-abc/preview.spec.ts` 直接渲染产品选项，不再拦截衬板资源或注入候选样式。
